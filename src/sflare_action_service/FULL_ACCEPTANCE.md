## 4. 基础命令与能力边界

| 检查 | 逐条操作 | 通过条件 |
| --- | --- | --- |
| 正常动作 | wave | busy→ready；轨迹、手势、停留、慢回零与已验收版本一致 |
| 空闲停止 | stop | 无运动、无新 SDK 连接，ready |
| 空闲恢复 | recover，且 /e_stop=0 | 只确认服务锁定，不清警、不上电、不运动 |
| 系统回零 | 确认姿态与环境后发 gozero | 只操作右臂，反馈到位后下电、断连；不尝试未接左臂 |
| 未知动作 | test_no_such_action | unknown_command，无运动；随后 stop 可回 ready |
| 单臂拒绝双臂动作 | fist、stretch、stretch_ready，逐条 | single_not_support，不连接左臂、不运动 |
| 忙时不排队 | wave 期间发 handshake | 不开始握手；wave 结束后也不补做 |
| 指令别名 | 空闲分别验证 挥手、bnzf | 与 wave 一致，每次只执行一次 |

双臂主机才验证三个双臂动作，并应先接好两侧控制器、确认配置为 dual。当前单臂机器跳过双臂运动验收，不为完成清单而改成 dual。

## 5. Stop、优先回零与退出

- [ ] wave 中途发送 stop：不再发送后续轨迹，完成安全下电与断连；无真实故障时回 ready。
- [ ] wave 中途发送 gozero：旧 EMI 会话清理后，再建立仅右臂的回零会话，不重叠连接。
- [ ] gozero 连发两次：合并，不执行两次回零。
- [ ] wave 中先发 gozero，随后立刻发 stop：stop 优先，不再启动排队回零；若回零已开始则停止当前回零。
- [ ] 动作清理期间发正常动作：拒绝，不排队；不会出现旧线程把新会话状态覆盖为 ready。
- [ ] Ctrl+C：工作线程自行收尾，下电后断连；不能在下电未确认时宣告安全退出。
- [ ] 原生 SDK 调用/线程未按时退出的分支只离线模拟：禁止回调线程跨线程清理句柄，进程退出，不启动新动作。

## 6. 实体急停与恢复

- [ ] wave 中按实体急停：停止动作，立即 physical_alarm；底盘同时收到零速通知。
- [ ] 急停保持按下时发送 wave、gozero、recover：均不能运动、自动清警或恢复 ready。
- [ ] 释放急停：不续跑旧动作、不自动回零。保留既有 recover 接口及上层联动，不新增自动恢复运动。
- [ ] 若既有上层会自动发送 recover，可维持已验收的“松开后恢复 ready”；单独运行本节点且没有该上层时，释放后需发送 recover。
- [ ] 清理期间提前发送 recover：必须等旧会话下电、断连确认后才 ready。
- [ ] 提前 recover 后再次按急停：撤销此前恢复确认，不能误报 ready。
- [ ] 恢复 ready 后重新发 wave，正常；不是自动续跑。
- [ ] 历史 check_error=-5029 且 /e_stop=0：不因此锁死服务；未知/按下时仍按报警处理。
- [ ] 仅有 -20039、没有本会话急停与 -5029 共同证据：不能伪装成正常停止，按网络故障退出。

## 8. 自动 Jog 脱限（重点新增）

该模块会重新上电并进行受限 Jog，不能当作“纯诊断”。真机仅在自然出现、已确认安全的软件限位状态下，由熟悉设备的操作者现场监护；不主动制造越限。否则本节以离线测试通过、真机待测记录。

- [ ] 必须同时有 -5031/-5032 报警及真实编码器/配置限位证据，/e_stop 明确为0、没有取消和其他阻断故障。
- [ ] 无越界时：在对应方向距限位3°范围内，且报警 Axis 明确或只有一个候选轴，才允许恢复。报警矛盾、多候选、无位置证据均拒绝。
- [ ] 真实越界轴按各自回到范围内的唯一方向逐轴恢复；不凭单个报警码让其他轴盲动。
- [ ] EMI 发送线程退出、底盘停止、下电确认、退出 EMI 确认以后，才允许进入恢复。
- [ ] 沿原版恢复过程：必要的编码器清警、上电、关节 Jog 模式、小步脉冲、每步停止后读编码器。
- [ ] 正上限只向减小方向；负下限只向增大方向。目标是对应限位内3°，不是零点。
- [ ] Jog 速度15、起始脉冲0.15s、自适应范围0.1～0.5s；90s/600脉冲上限与计划行程+1°硬限制保留。
- [ ] 无进展、方向错误、非有限/缺轴反馈、超预算、清理失败用离线模拟确认退出，不在真机上强造。
- [ ] 恢复过程中 stop 或实体急停能终止后续脉冲；当前 SDK 调用需先返回，随后停止 Jog 并下电，不跨线程抢句柄。
- [ ] 成功状态 limit_recovered；恢复失败 limit_recovery_failed，其他实际物理/网络/强电故障按其类别处理。
- [ ] 恢复后还原 Jog/坐标模式和当前 EMI profile，再次确认下电，最后断连。
- [ ] 不续跑原动作、不自动回零、不补做恢复期间发来的普通动作；成功后需重新发送指令。
- [ ] clear_alarm 只有原版 -5047/-5059 可作为非阻断诊断继续，其他失败停止恢复。

## 9. 外部占用与连接恢复

只在动作已结束、机械臂下电后，用既有手柄/控制客户端正常接管，不在运动中抢占。

- [ ] 外部持有连接时发送 wave：不得向对方句柄发下电、清警、运动或 disconnect。
- [ ] -20035 不直接证明占用：TCP不可达时 connection_failed；TCP可达但SDK拒绝连接时 handle_busy 只表示可能被外部占用，不保证根因。
- [ ] 进入释放监测后，每5秒探测；动作/回零指令不排队、不与探测并行。stop 可取消监测，实体急停始终有效。
- [ ] 外部正常释放后，只有 SDK 对所有配置臂连接成功、探测会话下电并断连完成，才 ready。
- [ ] 探测中不 add_robot、不上电、不设 profile、不清警、不运动；成功连接后必须去使能才断连。
- [ ] 已有上电外部客户端可能持续拒绝探测；不得强抢控制权，需先由外部正常释放。
- [ ] 探测下电失败/断连失败：进程退出，不继续报 ready。此分支只离线模拟。
- [ ] 单臂模式不探测未接左臂，避免重复出现之前 MODE 配错引起的连接错误。

## 10. 故障分类及退出策略

| 输入/条件 | 预期 |
| --- | --- |
| -5201 / -135 | physical_alarm，锁定，禁止自动回零/松手/脱限 |
| -5029 | 按实体 /e_stop 已释放与否过滤历史记录 |
| -5176 / -161 / -20236 | power_not_ready，不自动上电重试 |
| -20035 | 连接可用性监测，不能直接断定手柄占用 |
| -5031 / -5032 | 满足证据与门禁后自动脱限，否则拒绝 |
| -20038 / -20039 | 安全清理后 fatal_network，退出进程；仅原版可证实急停超时例外 |
| -5306 | invalid_target，不自动 Jog 或回零 |
| 下电/断连/发送线程清理未确认 | 退出进程，不复用会话 |

- [ ] stop 或“主体已完成”不能掩盖真实故障成为 ready。
- [ ] 网络/退出分支用离线模拟，不通过运动中断网验证。
- [ ] 手动 python3 启动时，进程退出不会自行重启；只有配置了重启策略的管理器才会重启。本轮未创建或修改正式 systemd 服务。
