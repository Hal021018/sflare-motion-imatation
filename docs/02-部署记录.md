## 4.1 按需脱限命令（新增）

| 项 | 值 |
|---|---|
| 命令 | `recover_limit` / `limit_recover` / `脱限` / `恢复限位` |
| 触发 | 游戏开局 `self_check` 发现 `overtravel_status != "0"` 后发送 |
| 行为 | 对**确实越界**的轴逐轴连续 Jog，回到 `限位±margin` 内侧后停 |
| 回零 | **不回零**（符合游戏流程） |
| 状态 | `releasing_limit` → `ready`（成功）/ `limit_recovery_failed`（失败） |
| 并发 | 有会话在跑时直接回 `busy`，不排队 |

参数（环境变量可覆盖，无需改代码）：

| 变量 | 默认 | 说明 |
|---|---:|---|
| `GAME_LIMIT_JOG_SPEED_PERCENT` | 50 | Jog 速度百分比；越大越快，过冲风险也越大 |
| `GAME_LIMIT_MARGIN_DEG` | 3.0 | 目标停在限位内侧多少度 |
| `GAME_LIMIT_POLL_SEC` | 0.05 | 位置轮询间隔 |
| `GAME_LIMIT_MAX_SECONDS` | 20.0 | 单轴最长 Jog 时间 |

安全门禁（`game_limit_recovery.py`）：

- 控制器 `get_status()[0]` 必须为 0；空/未知/非 0 一律拒绝。
- 只对 `position < lower` 或 `position > upper` 的轴动作，方向由越界侧唯一确定。
- 轮询期间每次重读急停；`stop` 可中断。
- 单轴超时 + 连续 2s 无位移（疑似被阻挡）双重保护。
- 任何异常路径先 `move_stop_jog`，再由协调器关 Jog 模式、还原坐标系、下电、断连。
- 全程不调用点对点运动，不回零。

实现位置：`game_limit_recovery.py`（判定与 Jog 循环）、`emi_coordinator.recover_limits_on_demand()`（SDK 生命周期）、`dual_arm_fist_stretch.py`（命令与状态）。
