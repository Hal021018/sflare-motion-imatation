# 遥操30秒采样与归位握手（2026-10-20）

> **历史文档**：30 秒自动采样已移除，仅保留 B 键触发，见 [07-B键采样握手](07-B键采样握手.md)。

> 已废止，仅作历史记录：用户要求移除30秒机制；当前实现仅B键触发。
> 以 `07-B键采样握手.md` 为准，不再按本文配置计时或timeout触发。

## 已实现范围

游戏侧状态机及Topic处理已实现，旧SDK V2.0.5355不变。
真实驱动尚未发布/消费本节内部握手，**不能宣称真机已自动采样归位**。
公开命令仍只有acts、arm_check、arm_demo；不新增B键替代命令或Service。

每次成功示范后生成唯一round_id，只发送arm_round，**不开始计时**。
驱动确认本轮遥操真正开始时发送started；从其中的实际同机单调时间开始计30秒。
抓取/松开遥操操作杆等短暂停顿不创建新session、不重新开始30秒计时。

```text
示范成功 → arm_round
真正开始遥操 → started → running
    ├─ 提前收到B事件 ─┐
    └─ 实际开始后30秒 ┴→ 原子抢占本轮唯一采样票据
                         → pause_for_sample
                         → 驱动停止下发遥操指令并确认paused
                         → SDK读取、评分、锁定快照、发布score
                         → reset_after_sample（唯一归位许可）
                         → 原驱动归位 → reset_done
```

B键和超时并发只允许一者抢占；重复开始不延长时限，重复B不重新采样或归位。
时间先到后再按B，也必须复用正在完成的同一票据；驱动不可独立再次request_reset。
采样发生在触发后的暂停确认点，有ROS传输/调度/制动延迟，不承诺硬件按键时刻零延迟快照。
若需精确还原硬件按键时间，需要驱动提供带时间戳的编码器历史，本版未实现该功能。

## 两个内部Topic

类型均为std_msgs/msg/String，JSON文本；同机单调时钟，非ROS墙上时间。

- 游戏 → 驱动：`/sflare_os/game/imitate/teleop_control`
- 驱动 → 游戏：`/sflare_os/game/imitate/teleop_event`

### 游戏 → 驱动

示范成功，只建立本轮标准，不自动遥操：

```json
{"command":"arm_round","round_id":"唯一轮次","timeout_sec":30.0}
```

超时或B键触发，请求暂停（尚不允许归位）：

```json
{"command":"pause_for_sample","round_id":"唯一轮次","session_id":"实际遥操会话","request_id":"唯一采样票据","reason":"timeout"}
```

reason为timeout或button。采样成功后：

```json
{"command":"reset_after_sample","round_id":"唯一轮次","session_id":"实际遥操会话","request_id":"同一票据","reason":"timeout","sampled":true,"allow_reset":true}
```

失败、急停或关闭节点则发送stop_without_reset（可带相同票据），不得解释为归位许可。
停止遥操并禁止本轮自动归位，不得绕过实体急停。驱动必须按三元组
round_id/session_id/request_id验证并幂等处理，每个票据最多执行一次归位。

### 驱动 → 游戏

确认实际遥操开始之后，发送：

```json
{"event":"started","round_id":"唯一轮次","session_id":"实际遥操会话","started_monotonic":12345.67}
```

started_monotonic必须来自同一测试机的单调时钟；不是示范结束时刻，也不是按键请求时刻。
游戏拒绝未来时间和延迟超过5秒的开始事件，防止过期事件延长或重开计时。

原right_init入口先阻止归位，然后发送：

```json
{"event":"button","round_id":"唯一轮次","session_id":"实际遥操会话"}
```

驱动收到pause_for_sample后，停止遥操指令并阻止其他路径启动归位，再确认：

```json
{"event":"paused","round_id":"唯一轮次","session_id":"实际遥操会话","request_id":"同一票据"}
```

只有收到reset_after_sample许可才执行原归位逻辑。归位结果：

```json
{"event":"reset_done","round_id":"唯一轮次","session_id":"实际遥操会话","request_id":"同一票据","success":true,"power_confirmed":"off"}
```

success和power_confirmed必须来自真实结果；未确认下电就不能发送off。
归位失败发送success:false。cancelled/emergency_stop事件撤销本轮；游戏也直接监听/e_stop=1，
清除标准并撤销计时和归位许可，不依赖驱动恰好通知到达。

## 失败与并发

- 等待paused超时5秒、采样工作超时15秒、归位确认超时45秒均报CAPTURE_FAILED。
- 超时不会假定成功，不发布未采到的分数，不继续归位；发stop_without_reset。
- 原生SDK阻塞调用不可强行杀线程；迟到结果凭轮次与票据失效，不再放行。
- 本轮遥操、采样或归位未结束时拒绝新的arm_demo。
- 急停后不能凭迟到ACK恢复，须重新建立有效标准与会话。
- 没有标准时不启动本轮采样。普通模式下B键行为不应因游戏节点离线而被改变；
  驱动需明确区分游戏模式及原有普通模式，不得暗中升级所有B键行为。

## 真机剩余工作

原服务提供者fish_driver_node的right_init会直接通知servo_control_node的request_reset。
另一份源码的set_moving入口切换遥操状态；需要在实际遥操开始处发布started，并在归位
通知前加入上述握手。不能靠被动监听服务、/button数字猜测或解析日志实现顺序保证。

运行安装目录与Haier_robot_ws_1.0.52源码版本尚未确认对应，未替换驱动二进制或servo控制模块。
本文件是已实现游戏侧所需的驱动协议，不代表驱动侧已经消费这些命令。

## 验证

机器端116项游戏回归通过。独立domain17假驱动ROS测试完成两轮：
提前B一次、30秒超时一次，各只产生一次score和一次归位许可；用加速单调时钟测试，
没有真实运动，也不是实际等待30秒的真机验收。另覆盖暂停缺失、采样失败、重复开始、
旧ACK、B与超时并发及直接/e_stop撤销等场景。
