# 动作模仿接口 V3：客户端 B 键采样后归位

日期：2026-10-20。

## 1. 版本状态与范围

这是本轮确认的客户端接入协议，后续用于无运动模拟及真机联调，**不是已经完成联调的声明**。
游戏端已有下述 Topic、轮次/会话校验及暂停→采样→放行状态机；客户端适配尚待实现与验证。
不修改原 `/arm_control_act` 服务，也不旁听或劫持 service request。
游戏业务全部使用 Topic；仅客户端最终归位沿用原机器人的 service。
SDK 保持 V2.0.5355；本地六动作默认 move_j，尚未完成本轮部署和真机验收。

## 2. 通信接口

| 方向（相对于游戏节点） | Topic | 类型 | 用途 |
|---|---|---|---|
| 输入 | `/sflare_os/game/imitate/cmd` | `std_msgs/msg/String` | 动作列表、自检、示范 |
| 输出 | `/sflare_os/game/imitate/result` | `std_msgs/msg/String` | 业务结果、评分、错误 |
| 输入 | `/sflare_os/game/imitate/teleop_event` | `std_msgs/msg/String` | 客户端遥操/B键/暂停/归位事件 |
| 输出 | `/sflare_os/game/imitate/teleop_control` | `std_msgs/msg/String` | 本轮标识、暂停请求、归位许可 |

所有 String.data 均为 JSON 字符串。ROS_DOMAIN_ID=15；先订阅，再发命令。
rosbridge 客户端可在同一 WebSocket 上发布和订阅以上 Topic。
事件不重放；断线后不得用缓存归位许可继续运动。

## 3. 业务命令和结果

输入示例：

```json
{"cmd":"acts","args":{}}
{"cmd":"arm_check","args":{}}
{"cmd":"arm_demo","args":{"act_name":"点赞"}}
```

动作实际列表以 acts 返回为准：指向(diagonal_point)、握手(handshake)、前伸递物(handover)、点赞(like)、举手过头(raise_head)、疑问(doubt)。
arm_check 为只读自检；arm_demo 会运动。忙时拒绝，不排队。

结果外层统一为 `{"type":"...","data":{...}}`：

| type | data | 含义 |
|---|---|---|
| acts | `{"list":["指向","握手","前伸递物","点赞","举手过头","疑问"]}` | 动作列表 |
| arm_check | `{"msg":""}` | 空为本次自检正常，非空为异常说明 |
| arm_demo | `{"state":"start"}` | 示范开始准备 |
| arm_demo | `{"state":"moving"}` | 进入运动段 |
| arm_demo | `{"state":"still"}` | 目标姿态完成后进入5秒展示段，每个游戏动作一次；准备等待不发布 |
| arm_demo | `{"state":"reset"}` | 示范开始回零 |
| arm_demo | `{"state":"end"}` | 示范成功结束，失败无end |
| arm_power | `{"state":"on"}` 或 `{"state":"off"}` | 本项目执行器读取并确认的电源状态 |
| score | 见第6节 | B键归位前姿态的评分 |
| error | `{"cmd":"teleop","code":"CAPTURE_FAILED","msg":"..."}` | 流程错误示例 |

示范可有多次 moving，当前六动作各有一次 still。外部驱动归位的电源状态不能用本项目示范事件推断。

## 4. B键完整顺序

```text
示范成功 → 游戏发布 arm_round
实际开始遥操 → 客户端发布 started
按B → 客户端暂缓原 right_init，并发布 button
游戏发布 pause_for_sample
客户端确认遥操输出已停止 → 发布 paused
游戏读取真实编码器 → 锁存角度与评分 → 发布 score
游戏发布 reset_after_sample（归位许可）
客户端校验许可、且只调用一次原 right_init
收到原服务 response → 客户端记录调用结果
确认真实归位完成 → 发布 reset_done
```

**不得发布 button 后立即调用 right_init，也不得仅看到 score 就归位。**
只有匹配本轮请求且包含 `sampled:true`、`allow_reset:true` 的 reset_after_sample 才是归位许可。
采样不是按B物理瞬间的硬件同步快照，而是B触发后、遥操暂停确认后的真实姿态，必须早于归位。
没有30秒自动采样，等待多久都不自动触发。

### 4.1 轮次与实际遥操开始

游戏在成功示范后发布至 teleop_control：

```json
{"command":"arm_round","round_id":"R1","capture_trigger":"button"}
```

`R1` 由游戏生成，每轮不同；客户端不得自行猜测。真实遥操开始后向 teleop_event 发布：

```json
{"event":"started","round_id":"R1","session_id":"S1"}
```

`S1` 由客户端为本次实际遥操生成唯一值，不能跨会话复用。started 仅登记会话，不是开始遥操的运动指令。

### 4.2 B键与暂停确认

客户端截住原B键归位调用，发送：

```json
{"event":"button","round_id":"R1","session_id":"S1"}
```

游戏返回 teleop_control：

```json
{"command":"pause_for_sample","round_id":"R1","session_id":"S1","request_id":"Q1","reason":"button"}
```

`Q1` 由游戏生成。客户端停止遥操输出、确认在途输出处理完成且不会有下一轮输入覆盖暂停后，发送：

```json
{"event":"paused","round_id":"R1","session_id":"S1","request_id":"Q1"}
```

paused 不是“收到暂停请求”的回执，不能仅设置UI状态后立即发送。
**如果客户端无法真正暂停产生机械臂运动的遥操输出，此条件仍不满足，不能声称只增加Topic便已可靠接入。**
客户端不负责伪造关节角度；评分由游戏节点读取真实编码器。

### 4.3 采样成功后放行归位

游戏先发布 score，再向 teleop_control 发布：

```json
{"command":"reset_after_sample","round_id":"R1","session_id":"S1","request_id":"Q1","reason":"button","sampled":true,"allow_reset":true}
```

客户端必须校验 R1/S1/Q1、command 和两个布尔值；每张许可只消费一次。
score 与许可在不同 Topic，网络接收顺序不能假定；以有效许可而不是先收到哪个事件作为调用条件。
然后沿用原 rosbridge service 调用（不由游戏节点创建新服务）：

```json
{
  "op":"call_service",
  "service":"/arm_control_act",
  "args":{"request":{"reqid":0,"act":"right_init","data":""}},
  "id":"b-reset-Q1"
}
```

服务类型：`aid_robot_msgs/srv/ArmControl`，提供者 `/fish_driver_node`。
`id` 用于 rosbridge 配对；与服务字段 reqid 不同。原请求参数保持兼容。

返回结构示例：

```json
{
  "op":"service_response",
  "service":"/arm_control_act",
  "result":true,
  "values":{"response":{"code":200,"reqid":0,"msg":""}},
  "id":"b-reset-Q1"
}
```

已知该 response 在归位流程后返回，但 **code200本身不证明编码器实际到位**，也不证明下电。
需核实实际运行服务是否可靠报告归位失败；否则仍需真实反馈确认，不能凭200填success=true。
不得对超时调用自动重试，原归位可能仍在执行。

### 4.4 归位结果

确认真实归位成功后向 teleop_event 发布：

```json
{"event":"reset_done","round_id":"R1","session_id":"S1","request_id":"Q1","success":true}
```

仅实际确认下电时才可额外加入 `"power_confirmed":"off"`；不确定则不填。
失败时发布同一消息但 `success:false`，游戏报错并结束该流程。
当前代码 success 仅接受JSON布尔值，不接受字符串"true"或数字1。

## 5. 失败、超时与重复消息

- 暂停确认等待5秒，采样等待15秒，归位确认等待45秒；均为故障保护，不触发自动采样或自动归位。
- 游戏失败时发送 `stop_without_reset`；客户端撤销未消费许可，停止本流程输出，不自行执行right_init。
- 急停或遥操取消时，客户端发送 `event:"emergency_stop"` 或 `event:"cancelled"`，包含round_id/session_id。
- 重复B仅处理一次；旧round/session/request不处理，不得跨轮次使用许可。
- 客户端需去重，不能每次收到重复reset_after_sample都调用归位。
- 急停、取消、断线、节点重启或过期许可后禁止继续归位；本轮不得自动重试旧请求。
- 当前协议未含跨进程的许可撤销确认，故本轮先做模拟；真实运动仍须遵守现有硬件急停和控制权保护。

## 6. 评分输出

游戏发布至 result：

```json
{
  "type":"score",
  "data":{
    "score":95,
    "j1":{"target":103.0,"actual":101.2},
    "j2":{"target":0.0,"actual":1.3},
    "j3":{"target":0.0,"actual":0.2},
    "j4":{"target":0.0,"actual":0.8},
    "j5":{"target":0.0,"actual":-0.4},
    "j6":{"target":0.0,"actual":0.1},
    "j7":{"target":0.0,"actual":0.0}
  }
}
```

数值仅示意。target=本轮成功示范的标准角度；actual=归位前锁存的实际角度，单位均为度。
spatial_joint_v2 评分保持不变；总分0—100，位置项70、动作专属方向归一化关节项30。

## 7. rosbridge Topic 封装示例

先订阅两个输出 Topic（result 和 teleop_control）：

```json
{"op":"subscribe","id":"game-control","topic":"/sflare_os/game/imitate/teleop_control","type":"std_msgs/msg/String"}
{"op":"subscribe","id":"game-result","topic":"/sflare_os/game/imitate/result","type":"std_msgs/msg/String"}
```

声明输入发布者，然后发布B事件：

```json
{"op":"advertise","topic":"/sflare_os/game/imitate/teleop_event","type":"std_msgs/msg/String"}
{"op":"publish","topic":"/sflare_os/game/imitate/teleop_event","msg":{"data":"{\"event\":\"button\",\"round_id\":\"R1\",\"session_id\":\"S1\"}"}}
```

这里 msg.data 是JSON字符串，不是嵌套对象。R1/S1/Q1均替换为当前实际标识。

## 8. 后续模拟验收清单（本轮未执行）

1. 无硬件：模拟示范成功、started、button、paused，确认只产出一次score和一次归位许可。
2. 归位服务先用假服务记录调用，确认采样完成前调用次数为0，许可后仅1次。
3. 验证重复B、旧票据、假暂停、采样失败、取消、断线不触发归位。
4. 核实实际客户端能够暂停遥操，以及right_init响应与真实到位的关系。
5. 条件确认后再安排真机，检查actual确为归位前姿态、返回后位置正常；不能用一次服务200代替验收。
