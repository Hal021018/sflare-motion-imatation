## 4. 接入前必须注意的问题（以下为候选源码发现，未以运动验证当前二进制）

1. `right_init`只归位，没有调用driver.stop()或power_off；下电在独立stop分支。
   不能把B归位完成等同于arm_power=off，也不能凭游戏侧end推测原驱动下电。
2. C++ init分支忽略notifyServoControl返回值；Python _execute_reset不把reset_arm的False向上传回。
   因此code200不能直接当作真实到位证明。后续reset_done须依据真实反馈和成功结果。
3. Pico输入在_poll_inputs中每轮按RG/LG重新设置moving；另有按键直接调用_execute_reset的旁路。
   单纯set_moving(false)可能被下一轮输入覆盖。需在实际输出入口统一暂停并确认在途输出已处理，
   游戏模式的所有归位旁路都必须经过同一票据，防止B重复归位或绕过采样。
4. Python ROS执行器只有一个线程，遥操Run循环另行运行。不能在服务回调内同步等待由同一执行器
   接收的Topic确认，否则会死锁。应采用非阻塞状态机或独立回调执行通道。
5. C++执行器为两线程，服务回调组MutuallyExclusive。新增ACK回调不能与等待方共用被占用的组，
   原有notify服务响应也不能被饿死。增加线程数量不等于已正确解决回调组互锁。
6. 模型轨迹发布结束与编码器实际到位不同。评分actual使用真实七轴角度，不能用模型current_q或
   /arm_joint_states占位值替代，也不应将规划已结束误报成实际归位完成。
