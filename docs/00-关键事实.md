## 2. 轴数与坐标约定（已与需求方确认）

- 控制器实际 **7 轴**：`robot.get_axis_number() == 7`。
- SDK 的 `LocationJ` 是 **定长 12 槽** 的 ctypes 结构（`PallasSDK/_types.py:543`）。
- `LocationJ.from_list()` 只填前 N 个槽，其余由 ctypes 零初始化（`_types.py:581`）。
- 官方书写规范用 **9 个值**：7 个关节 + 第 8/9 位为**外部轴**，当前用不上，**恒为 0**。
- 因此 9 值列表与 7 值列表送进 SDK 的**字节完全相同**（12 个 double，尾部全 0）。

❌ 早期误判：曾把 `MOVE_ACTION_POSITIONS` 的 9 维值当成"与 7 轴评分不匹配的缺陷"。**已撤销**。

推论：

| 数据 | 维度 | 含义 |
|---|---|---|
| `moveaction.data.positions` | 9 | **回显下发点位**，不是轴数 |
| `moveaction.data.zero_positions` | 9 | 回零目标（全 0） |
| `self_check.data.positions` | 7 | 真实轴数，来自 SDK |
| `calculate_score.data.*` | 7 | 评分只覆盖 7 个关节 |

**判断轴数只看 `self_check` 的数组长度，不看 `moveaction` 的回显。**

## 3. 固定动作服务的接口（黑盒，不改代码）

| 项 | 值 |
|---|---|
| 下发 | `/dual_arm_xcdl_action`，`std_msgs/String`，可纯名或 `{"command":"...","target":"..."}` |
| 状态 | `/dual_arm_xcdl_action_status`，`std_msgs/String`，`TRANSIENT_LOCAL` depth 1，1Hz 重发 |
| 急停 | `/e_stop`，`std_msgs/Int32`，0=释放 1=按下 |
| 节点名 | `emi_fixed_action_service` |
| 模式 | `PALLAS_ARM_MODE=single`（当前机器） |

动作：16 个单臂（`wave` `handshake` `like` `doubt` `raise_head` `shakehand` `slight_raise` `diagonal_point` `chin_rest` `handover` + 6 个底盘联动）+ 3 个双臂（`fist` `stretch` `stretch_ready`），另有系统命令 `stop` / `gozero` / `recover`。

状态取值 13 个：`ready` `busy` `physical_alarm` `recover_required` `power_not_ready` `connection_failed` `handle_busy` `limit_recovery_failed` `invalid_target` `unknown_command` `single_not_support` `fatal_network` `failed`。

### 3.1 没有"保持在最终姿态"

- 16 个单臂动作的最后一个关键帧全是 `[0]*7`，program 末尾统一 `move frame1 4.8s` → **演完必回零**。
- `action_program.py:127` 规定：最后一个 move 之后只允许 `wait`/`yaw_stop`/`linear_stop`，**schema 层就禁止停在非零位**。
- 播完走 `safe_cleanup_arm`：`emi_end` → `set_power_enable(False)` → 确认强电=0 → 断连（`emi_coordinator.py:442-460`）。**全仓库无抱闸控制。**
- 唯一终态非零的是 `stretch_ready`（`[60,14,-30,93,63,0,0]`，`auto_return_zero=false`，无 program），但同样在下电前只多停约 2.2s（0.2s 到位确认 + 2.0s 伺服平息）。

→ 「臂停在标准姿势让人模仿」在现有服务上**不成立**。可行替代：在动作的 `wait` 展示窗口（2.0–3.0s）内旁听 `/arm_joint_states` 抓标准。
