# 动作模仿项目功能说明

更新日期：2026-10-20。本文描述功能、模块职责与接入方式，不包含测试或排查记录。

## 1. 项目用途

机器人示范指定动作，用户随后摆出或通过遥操完成对应姿态。按B键后，系统采集归位前的真实关节角度，与本轮动作标准比较并输出评分；采样完成后才允许客户端执行原归位指令。
没有30秒自动采样机制，仅由B键触发。

## 2. 模块与职责

| 模块 | 职责 |
|---|---|
| 上位客户端 | 选择示范动作、管理实际遥操会话、发送B键事件、暂停运动输出、收到许可后调用原归位服务 |
| 游戏节点 | Topic命令处理、动作标准管理、采样握手、读取真实角度、评分与结果发布 |
| 游戏版动作服务 | 执行六个动作，控制灵巧手、展示停留、回零及安全清理，并发布动作阶段 |
| 原fish_driver_node | 保持现有right_init服务及归位流程，不增加本项目评分逻辑 |

当前游戏版六动作默认采用move_j；JSON保存原坐标、点序、手势和停留。
SDK要求使用旧版V2.0.5355，Python包与动态库必须配套，部署不能自动推断机器现有SDK版本。
move_j运行时间由原Profile和控制器决定，不直接沿用EMI分段时长。

## 3. 示范动作

| 显示名 | 内部名称 |
|---|---|
| 指向 | diagonal_point |
| 握手 | handshake |
| 前伸递物 | handover |
| 点赞 | like |
| 举手过头 | raise_head |
| 疑问 | doubt |

实际可选列表通过acts查询，客户端不应以示例动作名代替真实列表。

示范链路：接受arm_demo → 准备 → 运动到目标姿态 → 展示保持5秒 → 回零 → 成功结束。
成功示范后保存本轮评分标准并生成round_id；失败不发布成功end。

## 4. 动作阶段与电源状态

result中先根据type分流，再解析data，不应只根据state字符串判断业务。

| type | state | 含义 |
|---|---|---|
| arm_demo | start | 开始准备 |
| arm_demo | moving | 正在执行动作运动段，可多次出现 |
| arm_demo | still | 目标动作完成后的5秒展示段，六动作各一次 |
| arm_demo | reset | 开始回零 |
| arm_demo | end | 示范成功结束 |
| arm_power | on/off | 本项目执行器确认的上电/下电状态，不是示范阶段 |

准备阶段的短暂停留不发布still。仍须以真实阶段事件为准，不使用固定定时器推算运动完成。

## 5. B键采样与归位

```text
示范成功并建立本轮标准
  → 客户端登记实际遥操会话
  → 按B：暂缓原right_init调用，向游戏Topic发送button
  → 游戏请求暂停；客户端确认运动输出已暂停
  → 游戏采集真实编码器角度、锁存评分并发布score
  → 游戏发送归位许可
  → 客户端调用原right_init
  → 客户端确认真实归位结果并通知游戏
```

游戏节点不旁听fish_driver_node的request或response，也不替换其service。
客户端必须改造B键处理逻辑，不能仅同时转发两条消息；否则归位可能抢在采样前发生。
客户端还须能确认遥操运动输出真正暂停，不能只改变UI状态。
现有游戏端采用暂停后读取反馈，并非按B瞬间的硬件锁存。

轮次round_id和采样request_id由游戏生成；session_id由客户端生成。
各阶段使用标识配对，同一归位许可只能消费一次。取消、急停或失效许可不得继续触发归位。
原服务code200不直接等同编码器到位或下电，结果确认须有真实依据。

## 6. 评分

评分使用spatial_joint_v2：末端三维位置项占70分，动作专属关节项占30分，总分归一化至0—100。
关节项采用动作专属权重与正负方向归一化。相关阈值为可配置工程参数。

结果字段为score及j1至j7；每轴包含target（本轮标准角度）与actual（归位前实际角度），单位度。
actual使用真实编码器反馈，不使用占位关节Topic或归位后的姿态。
评分完成后锁存本次结果，随后归位不会改变已发布的评分内容。
