## 1. ROS 2 接口

真机 ROS_DOMAIN_ID=15，RMW_IMPLEMENTATION=rmw_cyclonedds_cpp。

| 名称 | 类型 | 作用 |
|---|---|---|
| `/sflare_os/game/command` | 服务 `sflare_game_interfaces/srv/GameCommand` | 游戏命令入口 |
| `/sflare_os/game/state` | 话题 `sflare_game_interfaces/msg/GameState` | 默认 5 Hz，可靠、TRANSIENT_LOCAL、depth=1 |
| `/dual_arm_xcdl_action` | 话题 `std_msgs/msg/String` | 游戏向固定动作服务发送动作/stop/recover_limit |
| `/dual_arm_xcdl_action_status` | 话题 `std_msgs/msg/String` | 动作服务状态，可靠、TRANSIENT_LOCAL |
| `/e_stop` | 话题 `std_msgs/msg/Int32` | 动作服务保护输入：1按下、0释放；不是游戏命令 |

服务定义：

```text
string request_type
---
string result
```

`result` 是 JSON **字符串**，上位机须再次解析。统一结构：

```json
{"success":"1","request_type":"self_check","code":"OK","message":"自检完成","data":{}}
```

`success` 是字符串 `"1"`/`"0"`，不是布尔值。动作与评分请求为同步服务；调用方须给足超时，不能收到响应前反复重发。游戏不排队；stop 不等待业务锁。

## 2. 命令

| request_type | 行为/主要 data |
|---|---|
| `self_check` | 只读硬件状态；positions、lower_limits、upper_limits（均7轴、度），overtravel_axes（1起始轴号），emergency_stop_status、overtravel_status、positioning_status、action_service_status |
| `release_limit` | 无越界返回 NOT_REQUIRED；有越界时代理 recover_limit 并复检。可能产生 Jog，不回零 |
| `moveaction` | 随机选动作，尽量避开最近两次 |
| `moveaction:<name>` | 指定动作；成功才建立本轮评分标准 |
| `calculate_score` | 读取当前机械臂关节，结合标准姿态正运动学计算新版评分；不运动 |
| `stop` | 发出 stop，立即清除本轮标准；响应只代表停止请求已发出，不代表已确认下电 |

动作名：`diagonal_point`（指向）、`handshake`（握手）、`handover`（递物）、`like`（点赞）、`raise_head`（举手过头）、`doubt`（疑问）。

`moveaction` 成功 data 包含：action_name、action_command、display_name、action_index、standard_deg、reference_positions、standard_source=`yaml`、hold_sec、estimated_duration_sec、service_status、scoring_arm、scoring_version、scoring_parameters。索引为动作名排序后从1开始，不建议上位机硬编码索引替代动作名。

正常顺序：self_check → moveaction → 动作展示并回零、服务ready → 用户通过既有流程形成待评分姿态 → calculate_score。新动作、stop、动作失败会使旧标准失效。当前没有摄像头/人体姿态输入，也没有新增手动拖动/力控功能。

## 3. 状态话题

GameState 四个字段均为字符串：

| 字段 | 含义 |
|---|---|
| positioning_status | 定位消息近期收到为1，否则0；默认未配置定位话题，通常为0 |
| emergency_stop_status | 0正常、1急停、-1未知/读取失败 |
| overtravel_status | 0正常、1超限、-1未知/读取失败 |
| current_state | idle/self_checking/releasing_limit/moving/calculating_score/stopping/error |

安全状态是最近一次自检缓存，不是连续硬件保护证明。不得用游戏缓存绕过动作服务或实体保护。

## 4. 新评分公式

版本：`spatial_joint_v2`。两组角度单位为度，XYZ 单位为毫米；不做±180°环绕。
标准 XYZ 与实测 XYZ 均用旧 SDK 的 `robot.to_cartesian(LocationJ)` 在**同一只读会话、同一工具/坐标配置**下求得。标准来自本轮动作的 YAML 关节坐标，实测来自编码器。它是模型正运动学结果，并非独立外部定位测量；控制器模型、零位或工具配置错误仍会影响结果。

配置在 `config/actions.yaml` 每个动作的 `scoring`：

| 参数 | 初值 | 意义 |
|---|---|---|
| position_share | 0.70 | 位置占70分、关节占30分 |
| position_tolerance_mm | 50 | 目标球半径；球内位置部分满分 |
| position_zero_mm | 300 | 位置误差达到此值时位置部分为0 |
| joint_tolerance_deg | 5 | 关节免罚容差 |
| joint_weights | 每动作不同 | 自动归一化为和1 |

这些阈值及权重是**可调工程初值，未经感知/人体科学标定**。

令位置距离 d=‖XYZ当前−XYZ标准‖，a=position_share，R=容差距离，D=零分距离：

```text
位置负罚分 Pxyz = -100*a*clamp((d-R)/(D-R), 0, 1)
```

每轴标准 r、实测 q、软限位[L,U]，有符号误差 Δ=q-r：

```text
方向可用行程 s = U-r（Δ>=0），否则 r-L
有效容差 t = min(joint_tolerance_deg, s)
方向归一化误差 e = clamp((abs(Δ)-t)/(s-t), 0, 1)
若 s<=t 则 e=0（该方向全部合法行程位于免罚容差内）
轴负罚分 Pi = -100*(1-a)*归一化权重wi*e
raw_score = clamp(100+Pxyz+sum(Pi), 0, 100)
score = floor(raw_score)  # 仅最终一次取整；实现消除10位小数后的浮点尾差
```

同幅度正负偏差会因剩余行程不同而产生不同罚分；剩余行程对称时仍相同。末端相同但构型不同，由关节项区分。当前不单独评价末端朝向/手指姿态。

负分制指**罚分项为负值**，不是最终输出负总分。位置很远时最多仍可保留30分关节分，不会因空间未到位而自动总分归零。满分需要位置进入目标区域且所有关节在免罚容差内。

### calculate_score.data 字段

| 字段 | 类型/意义 |
|---|---|
| scoring_version | string，spatial_joint_v2 |
| score / raw_score | 最终整数0–100 / 未取整浮点分 |
| action_name / action_index / scoring_arm | 本轮动作与手臂标识；当前真机适配器只读取右臂robot1 |
| reference_positions / current_positions | 7维角度数组 |
| reference_xyz_mm / current_xyz_mm | 同坐标配置下的3维XYZ |
| cartesian_source | 真机 sdk_forward_kinematics；假测试 fake_test_fixture |
| position_error_mm / target_region_reached | 空间距离 / 是否在目标球内（布尔） |
| position_score / joint_score | 位置部分 / 关节部分得分 |
| position_penalty / joint_penalties / total_penalty | 位置负罚分 / 7轴负罚分 / 总负罚分 |
| errors / signed_errors | 7轴绝对误差 / 有符号误差，度 |
| normalized_joint_errors / joint_weights | 方向归一化误差 / 本动作归一化权重 |
| joint_scores | 7轴浮点贡献分，合计为joint_score，**不再是旧版满分100的逐轴整数分** |
| scoring_parameters | 实际采用的归一化配置，便于上位机解释与复现 |

XYZ、关节或限位无效时拒绝评分，不降级到旧公式或捏造位置分。

## 5. 错误码

| code | 含义 |
|---|---|
| OK / NOT_REQUIRED | 成功 / 无需脱限 |
| ROBOT_BUSY | 已有操作或动作服务忙 |
| SERVICE_UNAVAILABLE | 服务无新鲜状态、无发布者或连接不可用 |
| EMERGENCY_STOP / POWER_NOT_READY / OVERTRAVEL | 保护、强电或限位问题 |
| ACTION_NOT_STARTED / ACTION_TIMEOUT | 未开始 / 未在动作估时+余量内完成；会发stop |
| ACTION_REJECTED / ACTION_FAILED | 动作拒绝或执行故障 |
| REFERENCE_NOT_READY | 本轮未成功完成动作或被stop清空 |
| OPERATION_CANCELLED | 旧操作结果因stop/新轮次失效 |
| UNKNOWN_ACTION / UNKNOWN_REQUEST | 未知动作/命令；无get_status或start_scoring接口 |
| JOINT_STATE_INVALID / OPERATION_FAILED / STOP_FAILED | 输入/底层异常/停止请求发送失败；当前FK错误通过OPERATION_FAILED返回 |

上位机按code判断，不依赖中文message。

